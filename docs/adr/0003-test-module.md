# ADR 0003: The generators are tested in a nested module, gentest

| | |
|---|---|
| Status | Accepted |
| Date | 2026-11-14 |
| Roadmap item | M2.1–M2.3 |
| Deciders | Claude, as owner |

## Context

models' root package holds only the metafile and its template (ADR 0001,
D11), and requires nothing. Its tests need genx (`genxtest`), i18n
(`i18ntest`, and the Go its generator writes), and sqlc's Go for a schema,
so the generated `Label()` methods compile against real types.

## Options

1. **Tests in the root module.** Simple, but every app that requires
   models would see genx and i18n in models' `go.mod`, and their versions
   would constrain the app's.
2. **A nested module, as i18n's `labels/`.** The root stays empty of
   dependencies; the test module may require anything.

## Decision

Option 2. `gentest` (`github.com/epistemer/models/gentest`) requires genx
`v0.2.0` (genx as a `tool` too), i18n `v0.2.0` and models through a
`replace` to `..`. It holds a small app, package `shop`, generated by its
own `genx.yaml`: sqlc from the shop fixture, then models' generators with
`table_prefix: shop_`, then i18n's. sqlc runs as
`go -C ../testdata/sqlc tool sqlc`, so the one pinned sqlc (M1.2) serves
both the fixtures and the app, and gentest doesn't require it.

Its tests: `genxtest.AssertGenerated` (genx check, `sqlc diff` included);
golden files for the defaults, other `dir` and `package` values and the
schema without enums, each rendered twice and compared; every refusal of
interface §6 against both generators; and `i18ntest` reading translations
back through `Label()`, the variables and `L10n(path)`.

## Consequences

- CI runs gentest's vet, tests, staticcheck and tidiness next to the root's.
- The `shop` package doubles as the example of what an app gets; M3.1's
  example adds a manifest an app would copy, with sqlc as its own tool.
